# 技能: anc-onboard

## 使用方式

```
/anc-onboard <客户 id 或工作目录> [托管|轻]
```

产出三样，缺一样不算走完：

1. **一棵能过校验的 vault**（org 真相源，进 git）；
2. **一台装好的机器**（托管形态：`anc apply` 七步跑完；轻形态：云上一份 vault + 一行接入）；
3. **一份体检报告**（探针 + 安全自检 + 每人收到自己 bot 的自我介绍）。

## 功能描述

**安装不是填配置文件，是一场访谈。** 创始人可以全程语音输入 —— 他不该被要求去改 markdown。

这条路上最贵的三个失败：

1. **把「装完了」当成「能用了」** —— 引擎起来了、`platform ready` 打出来了，人却回不了话。判据只能是**真回话过没有**，不是进程在不在（这正是 `anc probe` 的立身之本）。
2. **假装能自动化做不了的事** —— 去 IM 后台建应用、harness 登录（要 GUI 会话）、自动登录 / 防休眠决策，这三件**机器做不了**。写成「已自动完成」＝ 现场必卡，且卡在哪没人知道。
3. **访谈没做完就开始装机** —— 名单不全就会少发 bot，数据目录没定就会在装完之后重排 vault。装完再改结构，等于把装好的东西拆一半。

## 不变量（少一条就不算做完）

1. **向导与体检成对**：每步产出之后紧跟一次**能跑的**校验；不许出现「这一步做完了，但没人知道对不对」。
2. **做不了的显式列成 checklist**，不假装自动；每一项都要能标「过了 / 没过 / 跳过」。
3. **断点续走**：状态落在工作目录的 markdown 里，随时可以停下来、第二天接着走。
4. **口径从真相源来，不从对话来**：谁是管理员、谁接不接凭据、有几个 bot —— 一律以 vault 里的声明为准，不按「刚才他说过」算。
5. **装机走 `anc apply`，不手搓**：七步的顺序与凭据桥只有一份实现；自己拼一份，等于造第二份真相。
6. **人点头才往下走**：阶段 1 / 2 / 4 三处停下来等 human（CHECKPOINT）。
7. **不写历史**：`git commit` 归人；本技能只落文件、只跑只读校验。

## 执行流程

工作目录（`<客户id>` 与 `anc org init --id` 的 id 一致）：

```
<工作目录>/onboard-<客户id>/
├── 00-访谈.md      阶段 1 的问答原话与结论
├── 01-名单.md      阶段 2 的名单与角色决定
├── 02-资料.md      阶段 3 收了哪些材料、各走到哪一步
├── 03-装机.md      阶段 4 的 checklist 逐项状态
└── 04-体检.md      阶段 5 的探针 / 自检结果
```

### 阶段 1 访谈 ——「这棵树长什么样」

问出来，别猜出来：

- 你们公司是做什么的？
- 业务怎么分块？（客服 / 售前 / 供应链 …）
- 你们内部管这些东西叫什么？（→ 术语表）
- 手头的数据长什么样、大概多少、谁在用？

**CHECKPOINT 1**：把「公司名 / ascii id / 顶层数据目录」三个决定**念回给人听**，点头才起骨架。
`--id` 是小写 ASCII、会进服务名与 project 前缀，改它等于改名 —— 在这里定死最省事。

```bash
anc org init <vault 目录> --client "<客户名>" --id <ascii-id> --data 10-knowledge,20-ops --git
```

`anc org init` 出的是**骨架不是成品**，而且它会自己跑一次校验并把发现打出来 —— 那些发现**念给人听**，别自己咽掉。

**收口判据**：`anc org check <vault>` 没有红档。

### 阶段 2 名单 —— 一人一 bot

要名单（口述 / 表格 / 照片都行），每人要三样：**姓名、角色、IM 账号**。

- 成员与管理员：`anc org init --members` / `--admin`；已经有 vault 就直接改 `members/`
- 角色：先从内置角色模板匹配，不匹配再定制 —— 别从零写
- **管理员 = `company.admins`** —— 探针报红时「该交给谁」指的就是这里。名单不全，报红就没人接
- 谁**不接**平台凭据，就在真相源里显式声明 `unwired: true`（探针因此报灰，不报黄）—— 别用「没配」来暗示「不用管」

**CHECKPOINT 2**：把最终名单（谁、什么角色、谁是管理员）念回给人听。

**收口判据**：`anc org check <vault>` 零红档；`anc render <vault> --check` 无漂移。

### 阶段 3 资料 —— 首跑 ingest

「把手头的资料发我」（PDF / Excel / 照片 / 一段话都行）。**模型不直接写 vault** —— 走提案：

```
/anc-ingest-propose <材料> <vault>
anc ingest <vault> --from 提案.json --dry-run --patch
```

把那份 diff **连提案一起**交给人看；人点头之后再 `anc ingest <vault> --from 提案.json`（`git commit` 仍归人）。

**收口判据**：至少一份真材料落进 vault；`anc org check <vault>` 仍零红档。

### 阶段 4 装机 —— 能自动的自动，不能的列出来

**先自检环境**（在目标机器上跑）：

```bash
anc doctor <vault 目录>
```

**能自动的**：

```bash
anc apply <vault 目录>          # 先 dry-run，看七步会动什么，给人念一遍
anc apply <vault 目录> --apply  # 真装：渲染 → 装 daemon → 凭据桥 → 重启 → 回读
```

实测（Ubuntu 24.04 / 2 vCPU，干净用户从零装载，2026-10-15）：**装载本身约 1 秒**。
**时间不花在这里** —— 花在下面那三条 checklist 上。别拿「装得快」当成「上线快」。

**做不了、只能引导的 checklist**（逐项标 过了 / 没过 / 跳过，状态写进 `03-装机.md`）：

| # | 这一步 | 为什么不能自动 | 收口判据 |
|---|---|---|---|
| 1 | 去 IM 后台建应用，拿 `app_id` / `app_secret`。**要建几个由真相源里的成员数决定，不是固定值** | 平台后台没给第三方建应用的 API；且这一步牵着客户的账号与合规决定 | 每个**已接凭据**的 bot 在 `anc apply` 回读里出 `platform ready`；灰档的 bot 不算缺 |
| 2 | 用 GUI 会话给 harness 登录（Claude Code / Codex 等） | 登录要人在浏览器里点，可能还要过二次验证 | 真发一条消息，agent 回的是**人话**，不是 `Not logged in` |
| 3 | 自动登录 / 防休眠决策 | 是客户的运维偏好，不是技术默认值 | `anc doctor` 的「断电兜底」那一组能过；过不了就别承诺「断电自己起来」 |

凭据落进 `~/.anc/secrets.env`（**部署参数，不进 git**），权限 `0600`。**明文只住那里** —— 不写进 vault、不写进 config、不贴进聊天；其余地方一律引 `${ENV}`。

**CHECKPOINT 4**：三条 checklist 逐项念状态，没过就**明说「这条没过」**，不许含糊成「基本可用」。

**现场会踩的两条**（2026-10-15 实测，写在这里省一轮排查）：

- **干净的 Ubuntu 上没有 `unzip`** —— 发布包是 `.zip`，用 `busybox unzip`（基础系统自带）或 `python3 -m zipfile -e`。
- **包里的二进制没有可执行位**（`Compress-Archive` 不带 Unix 权限位）—— 解完必须 `chmod +x` / `install -m 0755`，不是保险起见。

### 阶段 5 验证 —— 体检 + 自我介绍

```bash
anc probe  <vault 目录>   # 运行态：每个 bot 到底回得了话没有（只读，不烧 token）
anc doctor <vault 目录>   # 环境与「断电兜底」自检
anc audit  tools          # 这一台机器上生效的工具表
anc audit  rules          # 生效的脱敏表（密钥值抹没抹）
anc audit  log <vault 目录> # 行使的流水，含被拒的那些
```

**读探针要按它的四档读**：绿 = 窗口内**真回过话** · 黄 = 没观测到（**不是没事，也不许报绿**）· 红 = 有消息但 agent 起不来 · 灰 = 真相源声明了未接凭据。

**刚装完就是「一个绿的都没有」是正常的** —— 还没有人发过消息。所以这一阶段的最后一步必须真的发一条：

> 让**每个成员**在自己的 IM 里收到自己 bot 的**自我介绍**（说清它是谁、代表谁、能查什么、查不到会说什么）。

**收口判据**：本技能**不替你判「上线了」**。它只把四样东西并排摆出来 —— 探针的每一档、checklist 的每一项、安全自检的结果、每人收到过自我介绍这个事实。**这一秒能不能用，由人判。**

## 断点续走

装机这件事一定会被打断（等凭据、等登录、等人回话）。状态就写在 `onboard-<客户id>/` 那五个文件里：

- **重新开始时先读它们**，别从头问一遍 —— 让人把同一句话回答三次，是最快搞砸信任的方式。
- **每个 CHECKPOINT 的结论写进文件**，不留在对话里（对话会丢，文件不会）。
- **已过的步骤不许悄悄重跑**：`anc apply` 是幂等的（连跑两次，第二次报「0 处漂移」），但 checklist 那几项的状态要人自己标。

## 边界

| 不该做的 | 为什么 |
|---|---|
| 替客户决定「业务怎么分块」「谁是管理员」 | 这是组织事实，不是技术参数；猜错一次，后面每条权限都错 |
| 把做不了的步骤写成「已自动完成」 | 现场必卡，而且卡在哪没人知道 |
| 自己拼一份装机步骤、不走 `anc apply` | 七步的顺序与凭据桥只有一份实现；抄一份就是第二份真相 |
| 把凭据或密钥值写进 vault / config / 聊天 | 明文只住 `~/.anc/secrets.env`，其余地方引 `${ENV}` |
| 拿 `git commit` 当收尾动作 | 历史归人。本技能只落文件、只跑只读校验 |
| 用「探针没报红」宣布上线 | 刚装完全黄是正常的 —— 没消息不等于没事 |
| 为了让流程走通而放宽真相源的校验 | `anc org check` 报什么就是什么；绕过去等于把问题推给下一个人 |

## 与兄弟能力件的分工

| 你要做的事 | 用哪个 |
|---|---|
| 把一家公司从零带到能跑（**本技能**） | `anc-onboard` |
| 把一份材料读成 ingest 提案 | `anc-ingest-propose` |
| 把原料蒸馏成可调用的能力 | `anc-distill` / `anc-distill-targets` / `anc-evolve` |

**轻形态**（团队里已有人用 coding agent、云上一份 vault、不部署 agent）复用阶段 1–3，阶段 4 换成「云上 vault + 一行接入」。
**未落地**：轻形态的代码与成员侧的能力件（加入 / 入库）本仓库还没有 —— 别在这里各写一套。

## 这一件为什么不是代码

「这家公司的业务怎么分块、谁是管理员、哪句话该进哪个字段」没有稳定规则 ——
写进代码就是过拟合，而且会在第一个真实客户身上碎掉。所以这一件落的是**流程与检查点**；
能固化的那部分（vault 结构、校验规则、渲染、装载、探针）全在 `anc` 里，且是**数据与命令**。

## 未验证

**本技能没有被真实客户端到端跑过。** 已经实测的只有它引用的那些命令本身：
`anc org init` / `org check` / `render --check` / `apply`（Windows 2026-10-07、Linux 2026-10-08，
以及 2026-10-15 干净机器从零装载 1.05 秒）/ `probe` / `audit` / `ingest` / `doctor`。
**阶段 1–3 的访谈脚本与阶段 4 的 IM 后台 checklist 都还没有真人走过一遍** ——
按 `skill/README.md` 的规矩，不得当「已通过」讲。
