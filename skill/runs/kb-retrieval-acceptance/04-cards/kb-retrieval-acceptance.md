# 能力卡：kb-retrieval-acceptance

**一句话**：把「一个自托管检索层到底能不能用」判成可复核的三个数；答案错的时候，先定该修哪一侧，再动手。

**授权口径**：本轮卡的全部原料为**本人自有**（自用语料 + 本人实测 + 本人工作笔记），无客户素材、无第三方素材、无个人信息。结论**是自用样例，不算客户验收**。

## I · 重述

一个检索层好不好，**不能问它「答得怎么样」** —— 那个问题把两件事混成了一件。

要拆成两问：

- 第一问：**找得着吗**？问的是「这道题，我事先指定的那篇源文档，有没有出现在它的 Top1」。
- 第二问：**照着找着的东西答对了吗**？问的是「把答案拿回那篇原文逐字对，对不对」。

拆开之后，会看到一个反直觉的形态：**第一问全对、第二问全错**。这时候如果再去看检索的分数，会觉得它「查得很好」；但答案本身是错的。所以：

**「检索好、答案错」这件事，本身就是一条判据。** 它的条数一多，就说明该修的不是检索 —— 修检索修不好那些题，因为检索根本没送错东西。

由此得出本卡最重要的行为：**先数这一类，再决定往哪边使劲**；以及**什么时候该停**。

**别忘了一件事**：这套判据是在自己的语料上跑出来的。写结论时必须把这句话放在最前面，不然过三个月就会有人拿它当效果承诺。

## A1 · 来源案例（真实运行，含失败分支）

一次完整的真实运行：自建语料 **28 篇**（443 块），本地单机模型，**8 条问题 + 1 条负例**，逐条走完「提问 → 引用 → 回答 → 拿回原文对拍」。

| 指标 | 实测值 |
|---|---|
| 检索 Top1 命中指定源文档 | **4 / 7** |
| 生成正确（逐条对拍） | **0 / 7** |
| 端到端耗时 | 合计 2242 s，均值 **4.7 分钟/条**（最短 136 s，最长 381 s） |
| 负例（语料里根本没有的题） | 核心达标（**没编任何数字**，开篇即说查不到）；但夹带了编造的项目状态 |

失败分支是这次最值钱的部分，三个错例形态各不相同：

1. **检索 0.995 精确命中，答案 10 段通用废话** —— 原文的正确内容一个字没进。
2. **检索 0.951 命中，答案编了另外一组问题** —— 五个问题一个都没对上。
3. **检索 0.989 / 0.986 命中两篇写着正确答案的文档，答案与原文相反**，还补了一串通用理由把**已被作废的结论**重新论证了一遍。

另有一条形态：**Top1 是 A 文档，答案却抄了 B 文档** —— 引用与生成之间也可能脱节。

> ⚠️ **这是自用样例，不是客户验收。** 有效分母只有 7 条，单库单域单模型单语料；换模型或换语料，这一格结论需要重测。

## A2 · 触发与适用

**该用它**（任意两条同时成立）：

- 目标机上**已经决定**叠一层自托管检索层（不是「要不要上」的阶段）；
- 手上**已经有语料**，能从中出题并写出出处；
- 你要的是一份**可判红**的结论，而不是「感觉还行」。

**不该用它**：

- 还在做**选型 / 分档**（「数据量到多少才上重档」）—— 那是上游议题的事，本卡不替它定阈值；
- **语料还没整理**、出不出带出处的问题集 —— 输入不成立，先整理语料；
- 想拿它的输出当**对外效果承诺** —— 它给的是「这条链路当前的运行特征」；
- 想验**权限、放行、跨域隔离、用量计量** —— 本卡不覆盖这四项（见 B 段）。

**与相邻能力怎么区分**：

- 与「知识库分档选型」区分：那个决定**要不要上**，本卡决定**上了之后能不能用**。
- 与「检索系统装机」区分：装机解决**跑得起来**，本卡解决**跑得准不准**。
- 与「提示词调优」区分：调优是**动手改**，本卡是**先判该改哪一侧**；本卡的结论可能是「别改检索」。

## E · 可执行步骤

### E0 · 先挡住不该进来的

对照 A2 的「不该用它」逐条自检。任一命中 → 停，先补前提。

### E1 · 出题（输入）

对语料逐条出题，**格式固定为两列**：

```
问题 | 我能在语料里对拍到的答案出处
```

- 出处写到**具体的篇 + 位置**（章节 / 小标题级），不许只写文件名；
- **必须带上出处再往下走** —— 出处先于答案写下，判据才不会随答案漂移；
- 题量按语料规模定，但**下限是能覆盖到每一类关键主张**；本题实际用了 8 条有效 + 1 条负例；
- 末条固定为**负例**：问一件语料里**根本没有**的事，且这件事的答案**可被外部核验为「不存在」**（别问一个语料外真有其事的东西 —— 那测不出「会不会编」）。

### E2 · 写下口径声明（输出的一部分，先写后跑）

在将要产出的报告最前面写死三句：语料是什么、模型是什么、**这批数据是什么身份**（自用样例 / 客户验收）。示例格式：

```
口径声明：语料＝<来源与规模>，模型＝<模型与部署形态>，
本次数据为<自用样例 / 客户验收>，结论仅说明该链路当前的运行特征。
```

### E3 · 逐条跑，只记能机器量出来的量

每条记录：**耗时 / 答案字数 / 引用条数 / 是否退化成通用话术**。

### E4 · 分腿算分（本卡的核心动作）

对每一条，独立填两格，**不许合并**：

| 格 | 判法 | 取值 |
|---|---|---|
| 检索 | 它的 **Top1** 是不是 E1 里为这道题**指定的那篇源文档**？命中「同主题的另一篇」**算不命中** | 命中 / 不命中 |
| 生成 | 把答案拿回**那篇原文**逐字对：**原文的关键断言有没有进到答案里？答案有没有说出与原文相反、或原文没有的东西？** | 正确 / 错误 |

**生成判错的判定顺序**（按严重度）：① 与原文相反 → ② 原文没有却说了 → ③ 原文的关键断言一条没进（即便结论碰巧对）→ ④ 答非所问。

### E5 · 数「决定性条目」，定主因侧

数出**「检索命中、生成错误」**的条数：

| 数出来 | 归因 | 下一步 |
|---|---|---|
| ≥1 条，且生成正确率很低 | **主因在生成侧** | 走 E6，**不要**先动检索 |
| 检索 Top1 大面积不命中 | 主因在检索侧 | 先修检索（提高 Top-K / 加 rerank / 按标题路径加权），再重跑 E4 |
| 两格都低 | 两侧都有问题 | **先修检索**（否则无法定位生成问题），修完重跑 E4 再回到本步 |

### E6 · 判停

**停手条件**：检索 Top1 命中率已达标、而生成正确率仍然很低。

**停下之后做什么**：换一个更强的生成模型，**用同一批问题重跑**，做对照 —— 不改题、不改语料，只改模型这一个变量。

> 这里的排序是**默认排序**，不是结论：原文把它标为「建议 / 预期」，理由（「错在生成、往下换更小模型是反方向」）成立，但「换更大模型就一定更好」**未经证实**。见 B 段。

### E7 · 输出（完成标准）

一份可复核的结论，**必须同时含这三样**：

1. **三个数**：检索 Top1 命中率 · 生成正确率 · 端到端单条耗时；
2. **逐条对拍表**：每题一行，含两格判定与一句对拍说明；
3. **一个方向**：主因在哪一侧 + 下一步动什么。

**外加一份留痕**：E2 的口径声明。

三条缺一条 → **不许交付**。

### 失败模式（如果 X 失败 → Y）

| 如果 | 那么 |
|---|---|
| 出题时写不出出处 | **停** —— 语料还没到能验的程度，回头整理语料，不要先跑再补出处 |
| 跑出来检索 Top1 大面积不命中 | 先修检索，**不要**据这批数据判生成侧 |
| 检索命中、生成却错 | 归因生成侧，**不要**动检索（本卡最主要的一个「不要」） |
| 答案通顺、有结构、还带表格 | **先怀疑它**：逐条拿回原文对拍，形态完整不是通过的证据 |
| 有引用条数 | **不能**据此判可信 —— 引对了文档仍可能答反 |
| 一个展示字段恒为 0 | 先用另一条路径核实际值，**不要**拿它当失败判据 |
| 结论要写进别处 | 同步改写所有已存在的旧口径，**不要**只在新文件里写对 |
| 对方问「那到底能不能上」 | 只给「哪条腿能用、哪条不能用」，**不要**替代客户做选型 |

### 🔴 检查点（必须停下来交给人）

| 位置 | 停下来做什么 |
|---|---|
| E0 之后 | 前提自检结果给 human 确认，再动 E1 |
| E5 之后 | 主因侧归因给 human 确认 —— 它决定后面所有投入的方向 |
| E6 之后 | 是否换模型 / 是否转去调检索 / 是否就此收口，**由 human 拍**。取消一个方向也是结论 |

## B · 边界与反例

**前提（不成立就别用）**

- 只在「**已经决定**叠重档」之后用。它不回答「该不该上」。
- 输入侧必须有**能出题、能写出出处**的语料。没有语料就没有判据。

**失效条件**

- **小分母**：本轮有效分母 7 条。这类结论只能说明「这条链路的运行特征」，**不能当统计**。
- **时效绑死**：结论绑在**具体模型 + 具体语料**上。换模型 / 换语料 / 换语料规模 → E4 到 E7 全部重跑。
- **不覆盖四项**：权限粒度与放行方式、跨域查询被拒且留痕、用量（token）可观测、在目标机器上的装机与重装时间 —— 本次**均未测**。上游明确要求后两项，属**未完成**，不许当成已完成。

**作者立场（可被推翻，但要知道自己在推翻什么）**

- 「先换更大模型、后调检索」是**默认排序**，原文自标为建议。要推翻它，需要同批问题在更强模型上的对照数据。
- 「问题在生成模型的指令遵循能力、不在提示词模板」是**假设**，原文用词是「更可能」。它不是本卡的前提。

**反例黑名单（不要做）**

- 不要把检索分与生成分**合成一个准确率** —— 主因会被埋掉。
- 不要因为「答案是通顺的」就判它对；**假绿是本卡要专门抓的形态**。
- 不要拿「有引用条数」当可信证据。
- 不要**绕过对拍**直接看答案「像不像」。
- 不要用通用常识补上没测的维度（权限 / 跨域 / 用量）。
- 不要把自用样例的结论说成客户验收。
- 不要替上游议题定**分档阈值**。
- 不要把「换更大模型更好」写成已验证的结论。
