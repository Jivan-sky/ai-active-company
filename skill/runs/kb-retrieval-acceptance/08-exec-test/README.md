# 08-exec-test —— M3 判据 #2 的调用记录（执行测试）

这一目录是**「这张卡被另一个 agent 在真实任务里调用过、有记录可查」**的原始凭证。没有它，判据 #2 只能算自述。

- **谁调的**：沙箱里的**另一个** harness（Claude Code 2.1.296）—— 不是生产这张卡的会话
- **怎么调的**：经 `Skill` 工具**真实调用**（`--output-format stream-json` 里可见），卡与仓库源 `diff -r` 逐字节一致
- **干了什么**：照卡跑完 E1–E7，产出 `report.md`，并停在 **E5 检查点**等人拍板
- **之后**：由第三方会话（生产卡的那一侧）做了**独立复核** —— 不复用它的数，改走检索接口重取排序；复核证据是 `verify-*.tsv|txt`，结论与口径修正写在 `../06-pressure.md` §5.3

## 目录

| 文件 | 是什么 |
|---|---|
| `report.md` | agent 交付的判定报告（含 E5/E6 两个检查点，未自判通过） |
| `qa-plan.tsv` | 题面；**出处先于答案**（先写死指定源 + 原文要点，再开跑） |
| `corpus/` | 第二份语料：4 篇合成《门禁与访客制度》，与来源语料无重叠，故意含一对新旧版本 |
| `eval-out/` | 11 份**逐条原始输出**（未加工）+ `timings.tsv` 逐条耗时 |
| `verify-top1.tsv` | 独立复核：检索接口逐题 Top1（不走 chat 引用列表） |
| `verify-channels.tsv` | 独立复核：分通道拆解（融合 / 仅向量 / 仅关键词） |
| `verify-rerank.txt` | 证据：rerank 为何没生效（配置 + 模型表 + 运行日志 + 代码分支 + query 改写） |

## 怎么复现

1. 起一套自托管检索层（本轮的落地方式登记在沙箱仓库，**不入本仓**）
2. 把 `corpus/` 4 篇灌进一个库，绑定嵌入模型与摘要模型
3. 按 `qa-plan.tsv` 逐条提问，收成 `eval-out/` 那种形态的输出
4. 用 `weknora search chunks "<题>" --kb <kb> --limit N --format json` 复现 `verify-top1.tsv` 与 `verify-channels.tsv`

> ⚠️ 复现前先读 `../06-pressure.md` §6 第 7 / 8 条：本轮**没记改写后的 query**，且**测的语料规模小于等于检索返回上限** —— 这两条都会让复现或结论失真。

## 脱敏

本目录只含**合成语料**与**模型原始输出**：无人名、无账号、无凭据、无本机绝对路径。
