# kb-retrieval-acceptance

**一句话**：把「一个自托管检索层到底能不能用」判成可复核的三个数；答案错的时候，先定该修哪一侧，再动手。

**先明确口径**：本能力把结论限定在「这条链路当前的运行特征」。用自己的语料测出来的结论**不是客户验收**，不能当对外效果承诺。

**来源**：`skill/runs/kb-retrieval-acceptance/`（蒸馏记录、四类分流、逐条对拍证据）。能力卡在 `04-cards/kb-retrieval-acceptance.md`。

---

## 适用与不适用

**该用**（两条同时成立）：

- 目标机上**已经决定**叠一层自托管检索层（不是「要不要上」的阶段）；
- 手上**已经有语料**，能从中出题并写出出处。

**不该用**：

- 还在做**选型 / 分档**（「数据量到多少才上重档」）—— 那是上游议题的事，本能力不替它定阈值。**碰到这类问题别只丢一句「不归我管」**：要说清它属于「分档 / 选型」哪一类上游议题，把问题原样交回；
- **语料还没整理**、出不出带出处的问题集 —— 输入不成立，先整理语料；
- 要验**权限、放行、跨域隔离、用量计量** —— 本能力不覆盖这四项；
- 想拿输出当**对外效果承诺**。

**与相邻能力怎么区分**：分档选型决定**要不要上**，本能力决定**上了之后能不能用**；装机解决**跑得起来**，本能力解决**跑得准不准**；提示词调优是**动手改**，本能力是**先判该改哪一侧** —— 本能力的结论有可能是「别改检索」。

## 步骤

### E0 · 先挡住不该进来的

对照上面「不该用」逐条自检。任一命中 → 停，先补前提。

### E1 · 出题（输入）

对语料逐条出题，格式固定两列：

```
问题 | 我能在语料里对拍到的答案出处
```

- 出处写到**篇 + 位置**（章节 / 小标题级），不许只写文件名；
- **必须带上出处再往下走** —— 出处先于答案写下，判据才不会随答案漂移；
- 题量下限：覆盖到每一类关键主张。本次出题 **8 条 + 1 条负例**，其中 **7 条计入分腿算分**（有效分母＝7；另 1 条未计入分腿）；
- **语料块数必须大于检索返回上限**（top-k / 条目上限）。否则整库都会被塞进 context，检索坏没坏都不改变结果 —— 这套测试对检索**不敏感**。（实测踩过：4 篇＝8 块，返回上限也是 8，11/11 回合的 context 都是整库全量）
- 语料里若存在**同主题的新旧版本**，必须**成对出题**（问同一个事实，只有一版是对的），并单列「旧版压制」一格 —— 这是检索最危险的失败形态，而且**融合前的两个通道可能各自独立地偏向旧版**
- 末条固定为**负例**：问一件语料里**根本没有**、且可被外部核验为「不存在」的事。不要问语料外真有其事的东西 —— 那测不出「会不会编」。

### E2 · 先写口径声明，再跑

在将要产出的报告最前面写死三句：

```
口径声明：语料＝<来源与规模>，模型＝<模型与部署形态>，
本次数据为<自用样例 / 客户验收>，结论仅说明该链路当前的运行特征。
```

### E3 · 逐条跑，只记能机器量出来的量

每条记录：耗时 / 答案字数 / 引用条数 / 是否退化成通用话术。另记两项，否则事后无法定位：**命中块的类型**（正文 / 自动摘要 / FAQ）与**实际送去检索的 query**（链路若会改写 query，记改写后的 —— 拿原始问句复现不出同样的排序）。

### E4 · 分腿算分（本能力的核心动作）

对每一条独立填三格，**不许合并**：

| 格 | 判法 | 取值 |
|---|---|---|
| 检索 | Top1 是不是 E1 里为这道题**指定的那篇源文档**？命中「同主题的另一篇」**算不命中** | 命中 / 不命中 |
| 生成 | 把答案拿回**那篇原文**逐字对 | 正确 / 错误 |
| 检索·块级 | 命中的那条**是不是含答案句的那一段**？只判盘级会放过「盘对了、块是另一段」—— 第三种失败形态 | 命中 / 不命中 |

**必须分通道各算一遍**（融合 / 仅向量 / 仅关键词）：只看融合分，看不出是哪条腿在拖 —— 实测踩过：融合 6/10 的背后是**向量 3/10、关键词 6/10**，向量通道恒把别篇的**自动摘要块**顶到第 1。

**生成判错，按这个顺序判**（严重度从高到低）：

1. 与原文**相反**；
2. 原文**没有**却说了；
3. 原文的关键断言**一条没进**（即便结论碰巧对）；
4. 答非所问。

### E5 · 数「决定性条目」，定主因侧

数出**「检索命中、生成错误」**的条数：

| 数出来 | 归因 | 下一步 |
|---|---|---|
| ≥1 条，且生成正确率很低 | **主因在生成侧** | 走 E6，**不要**先动检索 |
| 检索 Top1 大面积不命中 | 主因在检索侧 | 先修检索（提高 Top-K / 加 rerank / 按标题路径加权），再重跑 E4。**命中被取代的旧版要单列「旧版压制」条数**，不并入 Top1 不命中 |
| 两侧都低（检索与生成） | 两侧都有问题 | **先修检索**（否则无法定位生成问题），修完重跑 E4 再回到本步 |

### E6 · 判停

**停手条件**：检索 Top1 命中率已达标、而生成正确率仍然很低。

**停下之后**：换一个更强的生成模型，用同一批问题重跑做对照 —— 不改题、不改语料，只改模型这一个变量。

**换模型之前先做三变体消融**（同批题分别跑「只用 Top1」「用现有全量 context」「把 gold 强制置顶」）：三者的差异比换模型更快指到问题在哪一段 —— 只换模型会把「问题在 context 组装」误判成「模型不行」。

> 这条排序是**默认排序**，不是结论。它成立的依据是「错在生成，往下换更小模型是反方向」；「换更大模型就一定更好」**未经对照验证**。要推翻它，拿对照数据来。

### E7 · 输出（完成标准）

一份结论必须同时含：

1. **三个数**：检索 Top1 命中率 · 生成正确率 · 端到端单条耗时；
2. **逐条对拍表**：每题一行，含三格判定 + 一句对拍说明；语料有新旧版本时，**另单列「旧版压制」一格**；
3. **一个方向**：主因在哪一侧 + 下一步动什么。

外加 E2 的口径声明。**缺任一项 → 不许交付。**

## 失败模式

| 如果 | 那么 |
|---|---|
| E1 写不出出处 | **停** —— 语料还没到能验的程度，回头整理语料，不要先跑再补出处 |
| 检索 Top1 大面积不命中 | 先修检索，**不要**据这批数据判生成侧 |
| 检索命中、生成却错 | 归因生成侧，**不要**动检索（本能力最主要的一个「不要」） |
| 答案通顺、有结构、还带表格 | **先怀疑它** —— 逐条拿回原文对拍；形态完整不是通过的证据 |
| 有引用条数 | **不能**据此判可信 —— 引对了文档仍可能答反 |
| 某个展示字段恒为 0 | 先用另一条路径核实际值，**不要**拿它当失败判据 |
| 结论要写进别处 | 同步改写所有已存在的旧口径，**不要**只在新文件里写对 |
| 对话前文缺失（单轮 / 换了会话） | 先重建前提（语料、题面、口径）再判，**不要把 E6 的默认排序当结论用** —— 实测过：丢前文时模型的通用直觉会盖过卡里的默认排序 |
| 对方问「到底能不能上」 | 只给「哪条腿能用、哪条不能用」，**不要**替客户做选型 |

## 检查点（必须停下来交给人）

| 位置 | 停下来做什么 |
|---|---|
| E0 之后 | 前提自检结果给人确认，再动 E1 |
| E5 之后 | 主因侧归因给人确认 —— 它决定后面所有投入的方向 |
| E6 之后 | 是否换模型 / 是否转去调检索 / 是否就此收口，**由人拍**。取消一个方向也是结论 |

## 边界

- **前提**：只在「已经决定叠重档」之后用。它不回答「该不该上」。
- **小分母**：本轮有效分母 7 条。这类结论只能说明「该链路的运行特征」，**不能当统计**。
- **时效绑死**：结论绑在**具体模型 + 具体语料**上。换模型 / 换语料 / 换规模 → E4–E7 全部重跑。
- **不覆盖**：权限粒度与放行方式 · 跨域查询被拒且留痕 · 用量（token）可观测 · 在目标机器上的装机与重装时间。**均未测**，不许当成已完成。
- **作者立场**（可被推翻，但要知道在推翻什么）：「先换更大模型、后调检索」是默认排序，原文自标为建议；「问题在生成模型的指令遵循能力、不在提示词模板」是**假设**，不是本能力的前提。

## 反例黑名单

- 不要把检索分与生成分**合成一个准确率** —— 主因会被埋掉。
- 不要因为答案**通顺**就判它对；假绿是本能力专门要抓的形态。
- 不要拿「有引用条数」当可信证据。
- 不要**绕过对拍**直接看答案「像不像」。
- 不要用通用常识补上没测的维度（权限 / 跨域 / 用量）。
- 不要把自用样例的结论说成客户验收。
- 不要替上游议题定**分档阈值**。
- 不要把「换更大模型更好」写成已验证的结论。
