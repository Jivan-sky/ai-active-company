# 技能: anc-ingest-propose

## 使用方式

```
/anc-ingest-propose <原料路径或一段话> [目标 vault]
```

产出：一份提案 JSON（落成 `提案.json`）＋ 一句「谁提的、这份材料从哪来」。
**不落盘** —— 落盘是下一步、由人做。

## 功能描述

ANC 的真相源（vault）只许两类写者：**人手改 markdown** 与 **`anc ingest` 这条管道**。
第三方系统与模型**都不许直接写** —— 那不是「大家说好了不写」，是**没有那个入口**。

所以模型这一步只干一件事：**把材料读成「哪几个文件换成什么内容」**。
判断与留痕（校验、原子写、记审计）全在那条管道里，本技能一个字都不重复实现。

## 不变量（少一条就不算做完）

1. **只提案，不落盘** —— 不写 vault 里的任何文件，不 `git commit`。
2. **形状以机器为准** —— `anc ingest --dump-shape` 打出来的那份才是准的。
   别照本文抄一份：抄的那份迟早与代码不一样，而它管的是「什么东西能进真相源」。
3. **`content` 是整份文件全文**，不是补丁 —— 所以要先把现文件**整份读出来**，改完再整份交出去。
4. **抽不到就空着** —— 材料没说的锚点（domain / period / source）留空 = **待确认**，不许编。
   编出来的值会变成一条假绿：看的人以为这是事实。
5. **落点只有四处** —— `domains.md` · `projects.md` · `agents.md` · `members/<成员名>/<文件>`。
   材料要落到别处，意味着它要么不该进真相源，要么 vault 的结构该改 —— **不是这条管道的事**。

## 步骤

1. **读形状**：`anc ingest --dump-shape`
2. **读现状**：要改哪几个文件，先**整份读出来**；
   新建成员就照现有成员的 `persona.md` 抄骨架（键一个不少），再换成这个人的值。
3. **改**：只改材料真的说了的那几处。材料没说的**别动、别补、别美化**。
4. **出提案**：`{"by": …, "why": …, "writes": [{"path": …, "content": …}]}` → 落成 `提案.json`；
   `why` 里写明这份材料从哪来（文件名 / 链接 / 谁给的），`by` 写**谁提的**（认不出的人 = 拒收）。
5. **自检（必做）**：

   ```
   anc ingest <vault> --from 提案.json --dry-run --patch
   ```

   - **通过** → 把那份 diff **连提案一起**交给提材料的人，说清「会落哪几个文件、各是什么改动」；
   - **拒收** → 照着理由改（每条都带规则 id，例如 `member.role.missing`），别绕过它。
6. **落盘不由本技能做**：人看过 diff、点头之后，由他跑
   `anc ingest <vault> --from 提案.json`（那一步会记一条审计；`git commit` 仍归人）。

## 边界（写清，免得手滑）

| 不该做的 | 为什么 |
|---|---|
| 直接写 vault 文件、或直接 `git commit` | 历史归人；这条管道存在的全部意义就是「只有一个入口」 |
| 把 `content` 写成补丁 / 片段 | 补丁要匹配上下文，错一行整条都落不下去 |
| 编一个 domain / source / period 填上 | 空着 = 待确认；编出来 = 让人把假的当成事实 |
| 换成 YAML / 表格 / 一段自然语言交上去 | 形状只有一处说了算：`--dump-shape` |
| 先落盘，再问「这样可以吗」 | 顺序反了：**先给 diff，人点头，再落** |
| 把拒收当报错去重试 / 换条路绕 | 拒收说的是「这份东西不该落进去」，不是「服务坏了」 |

## 这一件为什么不是代码

「材料里哪句话该进哪个字段」没有稳定规则，写进代码就是过拟合 ——
所以这一件落的是**方法与边界**；而能固化的那部分（形状、白名单、校验、留痕）全在
`anc ingest` 里，且是**数据**（`--dump-shape` 直接打得出来）。
